# Документация разработки личной витрины товаров

Публичная адаптивная витрина для 20–100 товаров. Каталог редактируется через Google Sheets, фотографии хранятся в отдельной папке Google Drive, а страница публикуется как Google Apps Script Web App. Посетитель не входит в Google-аккаунт и не оформляет заказ автоматически: он связывается с продавцом вручную через Telegram, MAX, копирование сообщения или Google Form.

> Это первая реализация MVP. Google Sheets, Drive, Apps Script и Forms должны быть предварительно проверены с устройств и сетей целевой аудитории в России. Успешная работа у владельца, вошедшего в Google, не доказывает доступность для анонимного посетителя.

## Состав проекта

```text
.
├── .clasp.json.example
├── package.json
├── tools/setup/Setup.gs # инициализация и проверка каталога; не попадает в Web App
├── tools/setup/Pilot.gs # безопасные примеры и preflight для пилота; не попадает в Web App
├── PILOT_LAUNCH.md      # пошаговый план пробного запуска
├── src/
│   ├── appsscript.json
│   ├── Code.gs       # публичный Web App endpoint
│   ├── Config.gs     # Script Properties и публичные настройки
│   ├── Catalog.gs    # валидация, фильтрация и сериализация товаров
│   ├── Index.html    # структура публичной страницы
│   ├── Styles.html   # адаптивные стили
│   └── Client.html   # загрузка каталога, поиск и обращения
└── tests/
    └── catalog.test.mjs
```

## Требования

- Node.js 20 или новее — для локальных тестов.
- Аккаунт Google, которому принадлежат таблица, папка фото, форма и Apps Script-проект.
- Google Apps Script CLI `clasp` для загрузки кода из локального репозитория (не обязателен, если код переносится через редактор Apps Script вручную).

## 1. Локальная проверка

```bash
npm test
# или
npm run check
```

Тесты используют встроенный test runner Node.js и имитации Google Apps Script API. Они проверяют обработку каталога, безопасное заполнение шаблонных строк и предварительную диагностику, но не заменяют проверку в настоящем аккаунте Google, публикации Web App и мобильных клиентов Telegram/MAX.

## 2. Создание ресурсов Google

1. Создайте Google Spreadsheet, принадлежащий владельцу проекта. Скопируйте ID из URL — часть между `/d/` и следующим `/`.
2. В Google Drive создайте отдельную папку `Фото для публичной витрины`. Помещайте в неё только изображения, которые разрешено показывать любому человеку со ссылкой.
3. Создайте Google Form со следующими полями: `Код товара` (обязательное), `Ссылка на товар` (рекомендуется обязательное), `Как к вам обращаться` (необязательное), `Удобный канал ответа` (Telegram / MAX / телефон или другой способ), `Контакт для ответа` (обязательное), `Комментарий или вопрос` (необязательное). Ответы должны храниться в закрытой для посетителей таблице. Скопируйте ссылку формы и создайте ссылку предварительного заполнения, чтобы получить числовые ID `entry.<ID>` для полей кода товара и ссылки.
4. Проверьте, что все ресурсы доступны владельцу и что редактор каталога не получает права на редактирование кода Apps Script.

## 3. Создание Apps Script проекта и загрузка кода

Вариант с `clasp`:

```bash
npm install --global @google/clasp
clasp login
```

Создайте **standalone** Apps Script project в аккаунте владельца и скопируйте его Script ID из URL проекта. В корне репозитория выполните:

```bash
cp .clasp.json.example .clasp.json
```

Замените `PASTE_YOUR_APPS_SCRIPT_ID_HERE` на настоящий Script ID. Файл `.clasp.json` игнорируется Git и не должен содержать никаких других секретов.

Команда для загрузки файлов проекта:

```bash
clasp push
```

Не используйте `clasp push --force` без проверки изменений в редакторе Apps Script. Убедитесь, что в проекте загружены HTML-файлы и `appsscript.json`.

### Настройка Script Properties

В редакторе Apps Script откройте **Project Settings → Script Properties** и создайте свойство:

| Property | Значение |
|---|---|
| `SPREADSHEET_ID` | ID рабочей Google-таблицы |

ID таблицы не отправляется посетителю. Не храните токены, пароли или секреты в листе `Настройки`.

## 4. Инициализация Google Sheets

1. Создайте отдельный standalone Apps Script-проект для обслуживания каталога, который **никогда не будет опубликован как Web App**. Скопируйте в него содержимое `tools/setup/Setup.gs`, создайте Script Property `SPREADSHEET_ID` и запустите функцию `setupCatalogTemplate`. Оставьте этот проект доступным только владельцу.
2. Подтвердите необходимые разрешения от имени владельца. Служебный проект не входит в `src/` и не загружается командой `clasp push`; публичное приложение и функции обслуживания разделены намеренно, потому что Web App выполняется с правами владельца.
3. Убедитесь, что появились три листа: `Товары`, `Справочники`, `Настройки`.
4. Функция не должна перезаписывать листы, в которых уже есть данные. Если нужные листы были созданы ранее, проверьте их заголовки вручную.
5. Для безопасной проверки пустого листа можно скопировать `tools/setup/Pilot.gs` в служебный проект и запустить `addPilotSampleProducts()`. Он добавит только демонстрационные строки со статусом `Черновик` и откажется работать поверх заполненного каталога.
6. Заполните контактные настройки и замените демонстрационные строки реальными товарами. Сначала оставляйте их в статусе `Черновик`.
7. Запустите `validateCatalog()` для проверки активных товаров и `runPilotPreflight()` для общей проверки готовности. Расшифровка `ERROR`/`WARN` и ручные тесты приведены в [PILOT_LAUNCH.md](PILOT_LAUNCH.md).

### Контракт листа `Товары`

Первая строка должна содержать именно эти названия и в указанном порядке (код ищет столбцы по заголовкам, поэтому порядок технически не критичен):

| Заголовок | Правило |
|---|---|
| `product_id` | Уникальный постоянный код, например `ITEM-001`; латиница, цифры, дефис и подчёркивание |
| `title` | Обязательное название |
| `category` | Категория из листа `Справочники` |
| `description` | Обязательное текстовое описание; HTML не исполняется |
| `price_rub` | Число от 0 и выше |
| `quantity` | Целое число от 0 и выше |
| `size_or_variant` | Необязательный размер/вариант |
| `condition` | Необязательное состояние |
| `photo_1_url` | Основное HTTPS-фото, доступное без авторизации |
| `photo_2_url` | Необязательное дополнительное фото |
| `photo_3_url` | Необязательное дополнительное фото |
| `status` | `Черновик`, `В наличии`, `Зарезервирован`, `Продан` или `Скрыт` |
| `sort_order` | Необязательное число; меньшее значение выше |
| `updated_at` | Необязательное поле на будущее, в текущем MVP автоматически не заполняется |

Публикуются только товары со статусом `В наличии` или `Зарезервирован` и корректными обязательными полями. Код товара должен быть уникальным. При повторяющемся `product_id` все строки с этим ID скрываются. Товар со статусом `В наличии` и количеством 0 отображается как `Нет в наличии`, а не как свободный к продаже.

### Лист `Справочники`

- Столбец A, начиная со второй строки, содержит названия категорий.
- Начальные категории создаются функцией настройки, если лист пустой.
- Для добавления категории редактор дописывает её в конец списка.

### Лист `Настройки`

Столбцы `key` и `value`; используйте фиксированные ключи:

| key | Назначение |
|---|---|
| `store_title` | Заголовок витрины |
| `store_description` | Краткое описание |
| `seller_telegram_username` | Username Telegram без `@`; пусто — кнопка скрыта |
| `seller_contact_note` | Необязательное пояснение о связи |
| `max_enabled` | `TRUE` или `FALSE`, включает кнопку MAX |
| `google_form_url` | HTTPS-ссылка на Google Form |
| `google_form_product_id_entry` | Числовой ID поля кода товара из ссылки предварительного заполнения Google Form |
| `google_form_product_url_entry` | Необязательный числовой ID поля ссылки на товар |
| `delivery_note` | Условия передачи/доставки, если определены |

Настройки, которые не входят в allow-list, публичной странице не передаются.

## 5. Фотографии

Для первого запуска используйте публично просматриваемые изображения из выделенной папки Drive. В Google Drive настройте доступ так, чтобы изображение открывалось человеку с ссылкой. Не размещайте в этой папке личные документы. Код преобразует распространённые Google Drive URL вида `/file/d/FILE_ID/view` и `?id=FILE_ID` в URL для отображения; это не обходит закрытые права доступа. Проверяйте каждое фото в приватном окне без входа в Google.

## 6. Контакты и заявки

- **Telegram:** ссылка ведёт в чат с username продавца и передаёт предварительно заполненный запрос там, где это поддерживает клиент Telegram.
- **MAX:** ссылка `https://max.ru/:share?text=...` открывает выбор чата/канала с подготовленным сообщением. На десктопе поддержка этого deep link может отличаться; это надо проверять отдельно.
- **Скопировать запрос:** копирует шаблон обращения или показывает его в окне для ручного копирования.
- **Google Form:** показывается только при корректной HTTPS-ссылке Google Forms и заполненном ID поля `google_form_product_id_entry`. При наличии второго ID в форму также передаётся ссылка на карточку.

Шаблон содержит название, код, цену, URL товара и вопрос об актуальности наличия. Ни одна из кнопок не резервирует товар и не изменяет остаток автоматически. Заявки формы должны храниться в таблице, недоступной публичному пользователю.

## 7. Публикация Web App

В редакторе Apps Script выберите **Deploy → New deployment → Web app**:

- **Execute as:** владелец/пользователь, разворачивающий приложение.
- **Who has access:** любой пользователь, включая анонимного, если политика аккаунта это разрешает.

Сначала разверните тестовую версию. Убедитесь, что страница и фотографии открываются в приватном окне без Google-авторизации. После проверки создайте production deployment и используйте постоянную URL `/exec`. Изменения кода требуют обновления развертывания; изменения данных таблицы — нет.

## 8. Чек-лист проверки перед передачей

- [ ] Web App открывается анонимно на телефоне и компьютере.
- [ ] Таблица и ответы Google Form не открываются посетителю по прямой ссылке.
- [ ] Изменение цены, количества, описания и статуса видно после обновления страницы без повторного развёртывания.
- [ ] `Черновик`, `Скрыт` и `Продан` не публикуются.
- [ ] `Зарезервирован` явно отмечен; количество 0 не показывается как наличие.
- [ ] Поиск и фильтр категорий работают совместно; запрос без результатов даёт понятное сообщение.
- [ ] Текст товара отображается как обычный текст; HTML из таблицы не выполняется.
- [ ] Недоступное фото заменяется заглушкой.
- [ ] Telegram/MAX и форма обращаются к правильному товару.
- [ ] Редактор может вести таблицу, но не имеет прав на Apps Script-код.
- [ ] Telegram и MAX проверены на реальных устройствах; фактические результаты записаны.

## Ограничения текущей версии

- Нет корзины, оплаты, автоматического заказа или бронирования.
- Нет ботов Telegram/MAX.
- Нет автоматического обновления `updated_at`.
- Нет серверной формы для отправки заявок напрямую в Apps Script: заявки принимает Google Forms.
- Доступность Google-сервисов для российских пользователей не гарантируется кодом; её нужно проверить с реальных устройств и сетей.
